# SAAB 协议

SAAB（SpatialAudio Audio Bridge）是 [Apple 空间音频](Apple-Spatial-Audio.md) 渲染方式下，模组与 macOS 助手之间传输声场、头部姿态与渲染状态的本机协议。

协议定义同时存在于两处，修改时必须保持一致：

- Java：`src/main/java/io/github/obsidianplusplus/spatialaudio/apple/AppleBridgeProtocol.java`（编解码）与 `AppleAudioBridge.java`（连接与收发）
- Swift：`native/macos/SpatialAudioHeadTracker/main.swift`（音频桥客户端与渲染器）

## 连接

| 项目 | 说明 |
| --- | --- |
| 传输 | TCP，模组监听 `127.0.0.1` 上的临时端口，助手主动连接；启用 `TCP_NODELAY` |
| 启动参数 | 助手以 `--audio-port <端口> --audio-token <令牌>` 启动；令牌为 32 位小写十六进制随机字符，每次启动助手都会更换 |
| 认证 | 连接后第一条消息必须是 HELLO，且版本与令牌正确，否则模组立即断开；3 秒内未收到 HELLO 也会断开 |
| 并发 | 同一时刻只有一个连接；新的已认证连接会替换旧连接 |
| 超时 | 模组 5 秒内收不到助手的任何数据即断开（助手每 250 毫秒发送一次 STATUS）；模组向助手的一次写入阻塞超过 2 秒（助手不再读取）也会断开 |
| 重连 | 助手断开后每秒重试一次，直到游戏进程退出；连续 5 次连接刚建立（2 秒内）就被模组关闭时（例如令牌已随助手重启而更换），助手认定自己已过时并退出 |

## 消息头

所有字段为**小端序**。每条消息由 12 字节消息头与负载组成：

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u8[4]` | 魔数 ASCII `SAAB`（`53 41 41 42`） |
| 4 | `u16` | 消息类型 |
| 6 | `u16` | 保留，0 |
| 8 | `u32` | 负载长度（字节，不超过 4 MiB） |

## 消息类型

| 值 | 名称 | 方向 | 用途 |
| --- | --- | --- | --- |
| 1 | HELLO | 助手 → 模组 | 认证与能力上报 |
| 2 | CONFIG | 模组 → 助手 | 声场格式、缓冲目标、输出设备、头部追踪偏好 |
| 3 | AUDIO | 模组 → 助手 | 声场采样 |
| 4 | REQUEST | 助手 → 模组 | 请求音频帧（拉取模式） |
| 5 | HEAD | 模组 → 助手 | 头部姿态，约 100 Hz |
| 6 | STATUS | 助手 → 模组 | 渲染状态，每 250 毫秒 |

### HELLO（48 字节）

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | 协议版本，当前为 `1` |
| 4 | `u8[32]` | 令牌（ASCII） |
| 36 | `u32` | 能力位：bit0 可用 Apple 自动头部追踪（macOS 15+ 且具备 head-pose 授权），bit1 具备个性化空间音频授权，bit2 系统支持耳机运动数据 |
| 40 | `u32` | macOS 主版本号 |
| 44 | `u32` | 助手进程号 |

### CONFIG

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | 配置代次（每发送一次新配置加一） |
| 4 | `u32` | 采样率，48000 |
| 8 | `u16` | 声道数；0 表示空闲（尚未开始推送声场、声音引擎正在重新加载或已回退），助手停止请求、清空缓冲并停止音频引擎 |
| 10 | `u16` | 布局：0 空闲；1 Ambisonics（ACN 顺序、SN3D 归一化，阶数 = √声道数 − 1，对应 `kAudioChannelLayoutTag_HOA_ACN_SN3D \| 声道数`）；2 7.1（顺序 FL FR FC LFE BL BR SL SR，对应 `kAudioChannelLayoutTag_WAVE_7_1`） |
| 12 | `u32` | 标志位：bit0 优先使用 Apple 自动头部追踪 |
| 16 | `u32` | 目标缓冲帧数：助手让“环形缓冲中的帧数 + 已请求未到达的帧数”保持在该值附近 |
| 20 | `u16` | 输出设备名称字节数 n |
| 22 | `u8[n]` | 输出设备名称（UTF-8）；空表示跟随系统默认输出设备 |

### AUDIO

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | 配置代次 |
| 4 | `u32` | 帧数 f |
| 8 | `f32[f × 声道数]` | 交错排列的浮点采样 |

模组只在收到 REQUEST 后发送 AUDIO，发送的总帧数不超过该代次请求的总帧数（模组累计的未发送请求最多 48000 帧，即 1 秒，超出部分作废）。代次与助手当前配置不一致的 AUDIO 会被丢弃；负载长度必须恰好为 8 + f × 声道数 × 4 字节，否则助手视为协议错误并断开。

### REQUEST（8 字节）

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | 配置代次 |
| 4 | `u32` | 请求的帧数（可累计） |

### HEAD（20 字节）

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | 标志位：bit0 姿态有效 |
| 4 | `f32` × 4 | 四元数 x、y、z、w |

四元数是头部**相对屏幕**的旋转，已经过本模组的滤波、预测、回中与轴向设置，坐标系与 [SAHT 协议](SAHT-Protocol.md) 相同（x 右、y 前、z 上；左转偏航为正、抬头俯仰为正、右耳向下横滚为正）。助手换算为 AVAudio 坐标系（x 右、y 上、z 后）的听者朝向：

```text
f = q·(0, 1, 0)，u = q·(0, 0, 1)      （头部坐标系）
前向 = (f.x, f.z, −f.y)，上方向 = (u.x, u.z, −u.y)   （AVAudio 坐标系）
```

Apple 自动头部追踪生效时，助手忽略 HEAD。

### STATUS

| 偏移 | 类型 | 字段 |
| --- | --- | --- |
| 0 | `u32` | 标志位：bit0 引擎运行中，bit1 Apple 自动头部追踪生效，bit2 输出推测为耳机，bit3 声场已作为环境声床接入，bit4 引擎出错 |
| 4 | `u32` | 助手正在使用的配置代次 |
| 8 | `u32` | 环形缓冲中的帧数 |
| 12 | `u32` | 累计欠载次数 |
| 16 | `u32` | 实际使用的渲染算法原始值（7 为 `auto`，即 Apple 空间音频） |
| 20 | `u32` | 输出硬件采样率 |
| 24 | `f32` | 输出延迟（秒） |
| 28 | `u16` + 字节 | 输出设备名称（UTF-8） |
| … | `u16` + 字节 | 最近一次错误信息（UTF-8，无错误时为空） |

## 时钟与流量控制

助手是时钟的主人：音频硬件每消耗一部分数据，助手就补发 REQUEST，使缓冲量保持在目标附近；模组的泵线程收到请求才调用 `alcRenderSamplesSOFT` 渲染相应帧数。因此：

- 游戏的声音时钟跟随真实的音频硬件，不会漂移或越积越多；
- 助手暂停消费（例如切换输出设备）超过 0.3 秒，或助手未连接时，模组以实时速度空转渲染并丢弃，游戏中的声音照常播放完毕，不会卡住；
- 配置变化时代次加一，旧代次的请求与音频全部作废，避免格式错乱。

助手每 2 毫秒检查一次缓冲，缺口达到 128 帧才发送 REQUEST。它把 CONFIG 中的目标限制在 256～16384 帧之间，并且不低于音频硬件单次拉取帧数的两倍再加 128 帧，因此目标很小时实际缓冲会略多于“Apple 缓冲时长”。已请求的数据超过 1 秒没有任何音频到达时，助手把未完成的请求清零后重新计算。

## 助手命令行参数（新增部分）

| 参数 | 说明 |
| --- | --- |
| `--audio-port <端口>` | 音频桥端口；提供后助手连接模组并启动 Apple 渲染器 |
| `--audio-token <令牌>` | 连接令牌 |
| `--port 0` | 不读取耳机运动数据、不发送 SAHT（只做 Apple 渲染、且本模组不需要 AirPods 姿态时） |
| `--self-test` | 额外运行离线渲染自检：在无音频设备的环境中验证 Apple 引擎能把声场正确渲染到左右耳 |
