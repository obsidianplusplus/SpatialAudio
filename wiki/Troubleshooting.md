# 常见问题与排障

先打开调试叠加层（`/spatialaudio hud`）或执行 `/spatialaudio status`，根据显示的状态对照下表。`/spatialaudio renderer` 可单独查看当前的渲染方式与状态。

## 头部追踪状态

| 状态 | 含义 | 解决办法 |
| --- | --- | --- |
| 已关闭 | 追踪数据源为“关闭”，或渲染方式为“Apple 系统空间化立体声”（此时由 macOS 负责头部追踪） | 在设置中选择“自动”“AirPods”或“OpenTrack”；使用系统空间化立体声时这是正常状态 |
| 等待数据 | 尚未收到任何姿态 | macOS：确认已佩戴 AirPods 且它是当前输出设备；OpenTrack：确认输出为 UDP over network、目标 127.0.0.1:4242 并已 Start |
| AirPods 追踪中 / OpenTrack 追踪中 | 正常工作 | — |
| 助手启动中 | 正在解压或启动助手；首次使用会弹出权限请求 | 在弹窗中点击“允许” |
| 正在编译助手 | jar 中没有预编译助手，正在用 Xcode 命令行工具编译 | 等待 10~60 秒 |
| 缺少助手 | 没有预编译助手，也找不到 Swift 编译器 | 使用 Release 页面的 jar，或执行 `xcode-select --install` 后重启游戏 |
| 助手启动失败 | `open` 命令返回错误 | 查看游戏日志中的具体错误；打开助手文件夹手动运行 `--self-test` |
| 助手无响应 | 已启动但 15 秒内没有任何数据包 | 检查安全软件是否拦截；在“活动监视器”中确认 SpatialAudioHeadTracker 在运行；更换 UDP 端口后重启追踪 |
| 助手报错 | CoreMotion 报告错误 | 重新连接 AirPods，点击“重启追踪与渲染” |
| 系统版本过低 | macOS 低于 14 | 升级系统，或改用 OpenTrack |
| 设备不支持 | 系统或耳机不提供运动数据 | 确认耳机型号支持头部追踪（见 [兼容性](Compatibility.md#耳机)） |
| 未授权 | 拒绝了“运动与健身”权限 | 系统设置 → 隐私与安全性 → 运动与健身 → 打开 SpatialAudio Head Tracker，然后 `/spatialaudio restart` |
| 等待授权 | 权限弹窗尚未处理 | 在弹窗中点击“允许”（弹窗可能在游戏窗口后面） |
| 等待耳机 | 已授权但近 1 秒没有运动数据 | 戴上耳机；确认入耳检测开启；确认耳机是当前输出设备 |
| 端口被占用 | 设置的 UDP 端口已被其它程序使用。AirPods 助手会自动改用临时端口照常工作，但 OpenTrack 的数据无法送达 | 设置中更换“UDP 端口”，同步修改 OpenTrack 的目标端口，点击“重启追踪与渲染” |

## 渲染方式状态

状态面板、调试叠加层与 `/spatialaudio status` 中的“渲染方式：…”一行显示 [空间音频渲染方式](Apple-Spatial-Audio.md) 的运行状态。Apple 空间音频正在渲染时，这一行还会附带声场格式、估计延迟（助手缓冲 + 输出延迟，不含蓝牙传输）、头部追踪来源（“模组头部姿态”或“Apple 自动头部追踪”）、断音次数，助手具备个性化空间音频授权时再加上“个性化空间音频”。

| 状态 | 含义（界面提示原文） | 解决办法 |
| --- | --- | --- |
| 模组内置 | 正在使用模组内置的 OpenAL HRTF 双耳渲染。 | — |
| Apple 系统空间化立体声 | 请在游戏发声时点按菜单栏中的 AirPods 图标，在“空间化立体声”中选择“头部追踪”（本模组无法检测或代为打开此设置）。此模式只有左右声道，前后与高度方位会丢失。 | 按 [设置方法](Apple-Spatial-Audio.md#apple-系统空间化立体声兼容模式) 在 macOS 中打开 |
| Apple 空间音频不可用（系统不支持） | Apple 空间音频需要 macOS 14 Sonoma 或更新版本，当前已使用模组内置渲染。 | 升级 macOS，或改用“模组内置” |
| Apple 空间音频 · 等待助手连接 | 正在启动 macOS 助手并等待它连接。首次使用可能需要解压或编译助手，最长约 1 分钟。 | 稍候；追踪数据源为“自动”或“AirPods”时，可同时查看“头部追踪”一行的助手状态。这期间游戏声音照常推进但不会播放，声场开始推送后 12 秒内仍未连接（解压、编译的时间不计入）会自动回退 |
| Apple 空间音频 · 正在启动渲染引擎 | 助手已连接，正在建立 Apple 空间音频引擎。 | 通常一闪而过；长时间停留请查看 `logs/latest.log` |
| Apple 空间音频 · 正在渲染 | Apple 空间音频正在渲染。若菜单栏 AirPods 图标中为 SpatialAudio Head Tracker 列出了“空间音频”，请设为“关闭”，避免重复空间化。 | — |
| Apple 空间音频 · 渲染引擎出错 | 助手报告 Apple 渲染引擎出错（切换输出设备时可能短暂出现）。持续 5 秒以上会自动回退到模组内置渲染。 | 确认输出设备可用；刚切换过输出设备时稍等片刻 |
| 已回退到模组内置渲染 | Apple 空间音频未能启用，已自动改用模组内置渲染。排除问题后点击“重启追踪与渲染”或执行 /spatialaudio restart 即可重试。 | 括号中附有回退原因，见下表 |

“Apple 系统空间化立体声”“Apple 空间音频不可用（系统不支持）”“Apple 空间音频 · 渲染引擎出错”“已回退到模组内置渲染”这四种状态会额外显示一行提示；用 `/spatialaudio renderer <方式>` 切换到这些状态时，命令也会给出同样的提示。

### 回退原因

回退时，聊天栏会提示“[空间音频] Apple 空间音频未能启用，已改用模组内置渲染：<原因>。排除问题后执行 /spatialaudio restart 即可重试。”（进入世界前发生的回退在进入世界时提示，此时需要开启“设置提示”），状态提示的括号中也附有原因：

| 原因 | 何时出现 | 解决办法 |
| --- | --- | --- |
| 无法创建本机音频桥（…） | 无法在 `127.0.0.1` 上监听 TCP 端口 | 括号中是系统给出的错误；检查安全软件是否拦截本机连接 |
| 无法创建 OpenAL 回环设备 | `alcLoopbackOpenDeviceSOFT` 失败 | 确认没有其它模组或启动器替换 Minecraft 自带的 OpenAL Soft（26.3 自带 1.25.2，支持回环设备），并查看日志 |
| OpenAL 不支持回环设备（ALC_SOFT_loopback） | OpenAL 缺少回环扩展 | 同上 |
| OpenAL 不支持 Ambisonics 回环输出（ALC_SOFT_loopback_bformat） | 所选声场格式为 Ambisonics，但 OpenAL 缺少 B-Format 回环扩展 | 把“声场格式”改为“7.1 环绕声”，或恢复 Minecraft 自带的 OpenAL Soft |
| OpenAL 最高只支持 N 阶 Ambisonics | 所选阶数超过 OpenAL 的上限 | 选择更低阶的“声场格式” |
| OpenAL 回环设备不支持所选声场格式 | 回环设备不接受该声道配置（48 kHz 浮点） | 换一种“声场格式” |
| OpenAL 无法在回环设备上创建上下文（错误 0x…） | 用即将使用的属性试建上下文失败 | 换一种“声场格式”；附上日志反馈 |
| 助手无法启动（…） | 助手启动失败、找不到助手或系统版本过低 | 按 [头部追踪状态](#头部追踪状态) 中的“缺少助手”“助手启动失败”处理；括号中是具体错误 |
| 助手在 12 秒内没有连接 | 助手已启动，但声场开始推送（或与助手断开）后 12 秒内没有连上音频桥 | 在“活动监视器”中确认 SpatialAudioHeadTracker 在运行；检查安全软件；使用 [自备助手](Apple-Spatial-Audio.md#自备带授权的助手可选) 时，确认它是用当前版本的源码构建的 |
| Apple 渲染引擎持续出错（…） | 助手报告引擎出错超过 5 秒 | 括号中是助手报告的错误；确认输出设备可用，重新连接耳机后重试 |

排除问题后，点击设置界面中的“重启追踪与渲染”、执行 `/spatialaudio restart`、重新选择渲染方式或修改“声场格式”，都会清除回退状态并再次尝试。

## 常见问题

### 转头时声场转动得太多 / 方向感混乱

系统与模组各做了一次空间化与头部追踪。按当前的渲染方式检查（见 [不同渲染方式的系统设置](macOS-AirPods.md#不同渲染方式的系统设置)）：

- **模组内置**：macOS 的系统空间音频没有对 Java 关闭。见 [为什么要关闭系统空间音频](macOS-AirPods.md#为什么要关闭系统空间音频)。
- **Apple 空间音频**：如果菜单栏 AirPods 菜单中为 **SpatialAudio Head Tracker** 列出了“空间音频 / 空间化立体声”，把它设为“关闭”。助手输出的已经是 Apple 渲染好的双耳声音，Minecraft 本身此时不直接发声。
- **Apple 系统空间化立体声**：本模组已停止自己的头部追踪，OpenAL 听者不随头部旋转，声场只由 macOS 转动。

### 向左转头，声音也往左跑

某一轴方向相反。打开调试叠加层：向左转头偏航应为正值、抬头俯仰应为正值、向右歪头横滚应为正值；方向相反就开启对应轴的“反转”。

### 静止不动，声场却慢慢偏转

陀螺仪漂移。按 `F6` 回中；确认“漂移校正”已开启；可把“漂移校正时间常数”调小。

### 转头时声音延迟、跟不上

- 适当增大“姿态预测”（例如 50~70 ms）；
- 增大“平滑速度系数”（快速转头时滤波更跟手），或提高“平滑最小截止频率”（静止时更跟手，但抖动略多）；
- 蓝牙音频本身有 150~250 ms 延迟，这是 AirPods 的硬件限制。
- Apple 空间音频方式下头部姿态不经过音频缓冲，“Apple 缓冲时长”只影响声音事件的延迟，不影响转头；Apple 自动头部追踪生效时，本模组的预测与平滑设置不起作用。

### 急停时声场“过冲”

减小“姿态预测”。

### 听不出上下、前后

- 使用“Apple 系统空间化立体声”时这是预期结果：两声道立体声只携带左右信息。需要前后与高度方位请改用“模组内置”或“Apple 空间音频”；
- 使用“Apple 空间音频”时，确认“声场格式”不是“7.1 环绕声”（只有水平面）；方向最精确的是“3 阶 Ambisonics”；
- 模组内置渲染时，确认状态面板中 HRTF 为“已开启”（Apple 两种方式下显示为“由 Apple 空间音频引擎渲染”或“由 macOS 空间化立体声渲染”，HRTF 相关设置不起作用）；
- 尝试更换 HRTF 数据集（见 [自定义 HRTF 数据集](Spatial-Audio-HRTF.md#自定义-hrtf-数据集)），HRTF 与个人耳廓的匹配度对前后、上下分辨影响很大；
- 头部追踪本身也能帮助大脑分辨前后：轻微转头时声音的变化方向能消除前后混淆。

### HRTF 显示“被拒绝”或“输出格式不支持”

输出设备不是立体声（例如被设置为多声道）。在系统声音设置中把输出设为立体声，或在设置中保持“HRTF 双耳渲染：强制开启”（会请求立体声 HRTF 输出）。

### Apple 空间音频方式下没有声音

1. 看“渲染方式”一行的状态（见 [渲染方式状态](#渲染方式状态)）。“等待助手连接”期间游戏声音照常推进但不会播放；超过 12 秒仍未连接会自动回退到模组内置渲染并恢复声音。
2. 状态为“正在渲染”却听不到：声音此时由 **SpatialAudio Head Tracker** 播放，而不是 Java。它输出到 Minecraft“音乐与声音”中选择的设备；选择“系统默认”时跟随 macOS 当前的默认输出设备。检查该设备与 macOS 音量。
3. 状态面板中的断音次数持续快速增加时，说明助手的缓冲经常被取空，见下一条。
4. 仍然没有声音：切回“模组内置”确认游戏本身有声音，然后附上日志与助手 `--self-test` 的输出（运行方法见 [助手从哪里来](macOS-AirPods.md#助手从哪里来)）反馈。

### Apple 空间音频方式下声音断断续续、有噼啪声

助手的缓冲来不及补充（状态面板中的“断音”次数会增加）。适当增大 设置 → Apple 空间音频 → **Apple 缓冲时长**（默认 30 毫秒，可调 10~200 毫秒）。缓冲越大，声音事件的延迟越大，但头部姿态不经过这个缓冲，转头的响应不受影响。切换输出设备时助手需要重建音频引擎，声音可能短暂中断。

### 声音在室内太“空”或混响太长

降低“混响强度”；或把常用的建筑材料设置更高的吸声系数（见 [方块材质覆盖](Configuration.md#方块材质覆盖)）。

### 墙后的声音太小 / 太大

调整“遮挡强度”。觉得门外的声音方向跳动，可以关闭“绕射重定向”。

### 性能下降

降低“环境探测射线”“绕射搜索范围”或“每刻计算预算”；极端情况下可以关闭“声学模拟”，只保留 HRTF 与头部追踪。

### 与 Sound Physics Remastered 一起用

默认由 Sound Physics 负责声学，本模组只做 HRTF 与头部追踪，两者可以共存。

### 游戏退出后助手还在运行吗？

不会。助手每 0.5 秒检查一次游戏进程，游戏退出后自动结束；游戏退出时也会主动结束它。

### 如何完全卸载

删除 `mods` 中的 jar、`config/spatialaudio.json` 与 `config/spatialaudio/` 文件夹即可。若想撤销权限，在 系统设置 → 隐私与安全性 → 运动与健身 中关闭 SpatialAudio Head Tracker。

## 反馈问题

请在 [Issues](https://github.com/obsidianplusplus/SpatialAudio/issues) 中附上：

1. `/spatialaudio status` 的输出（其中包含渲染方式与状态）；
2. `logs/latest.log`（搜索 `SpatialAudio`）；
3. 系统版本、耳机型号、模组列表；
4. 使用 Apple 空间音频时，再附上“声场格式”设置与助手 `--self-test` 的输出，并注明是否使用了自备助手。
